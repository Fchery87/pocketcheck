# Assessment of the repository review

This assessment checks the supplied review against the workspace at commit `ee318d0`, including its local `data/artifacts/baseline.json`. Most persistence and board-pricing findings warrant implementation. Several runtime claims are incorrect, and several statistical recommendations need a new experiment rather than an immediate production change.

The assessment is read-only apart from this document. No provider requests, live database queries, migrations, or artifact replacements were performed. Source locations below refer to the inspected commit.

## Evidence and limits

The following targeted command passed all 70 tests in six files:

```sh
./node_modules/.bin/vp test run tests/sources/play-by-play.test.ts tests/sources/nws.test.ts tests/model/anchor.test.ts tests/providers/pick-explanation.test.ts src/lib/server/analysis/primary.test.ts src/lib/server/analysis/board-run.test.ts
```

Separate local probes exercised malformed NWS responses, a slow response body, play-by-play summaries, board parsing, backup shapes, and the saved artifact's outcome distribution. Passing existing tests does not disprove defects outside their assertions. The full application check, browser acceptance, and database verification were not run. Database concurrency, PostgreSQL restore round trips, mobile overflow, and back-navigation behavior need runtime verification before a fix is declared complete.

“Confirmed” below means that the implementation supports the reported mechanism, with any runtime limits stated. It does not mean the user's saved journal was inspected or proven to contain affected records.

The architecture's separation of analyses, model picks, and placed contracts is worth preserving. Code-computed mathematics, durable provider attempts, and isolated verification are also sound choices. The review's stronger praise exceeds the evidence: learned key-number weights are artifact estimates, not universal NFL constants, and good architecture does not prove a betting edge.

ADRs 0003 and 0004 govern anchor behavior and prospective evaluation. ADR 0005 governs numeric explanations. Successor decisions must explain changes to those contracts. The current `prospective-2026-10-26` thresholds, frozen forecasts, and historical classifications must not be rewritten to benefit from new methods. A new forecasting artifact needs its own registration; an evaluation change needs a successor protocol. Those are related but distinct changes.

## Missing capabilities and implementation order

The six proposed capabilities mostly describe real omissions. Their priority differs from the review's correctness fixes.

| Capability                                            | Assessment and recommendation                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Opposing price on the analysis page                   | Strongly recommend resolving this now because it repairs a documented forecasting workflow. Retiring that forecast path is a valid alternative only with an explicit product decision and revised copy.                                                                                                                     |
| Aggregate CLV and calibration in the app              | Useful after saved-record integrity is fixed. Show availability, sample size, contract comparability, and observed versus inferred comparisons. It is a reporting feature, not proof that any market is released.                                                                                                           |
| Schedule-assisted settlement                          | Useful. Prefill from a proven result source and append a deliberate notice with provenance. Do not silently regenerate grades or use the current schedule to backfill a frozen snapshot.                                                                                                                                    |
| Pagination, season grouping, and correction selectors | Sensible workflow improvements as records accumulate. A selector that identifies the prior notice is preferable to manual UUID entry. Pagination priority depends on journal size.                                                                                                                                          |
| Active non-QB injuries and manual QB overrides        | The plumbing is incomplete, but non-QB modeling is deliberately inactive. The research note requires publication-time provenance, snap coverage, and validation. Add structured QB evidence only with source time and explicit override semantics. Do not activate unfitted injury weights just because helper code exists. |
| LAN access protection                                 | Strongly recommend when LAN entry is part of normal use. Apply it consistently to reads, downloads, restores, and paid actions.                                                                                                                                                                                             |

My implementation order is:

1. Preserve the record. Fix quotes, complete CLI export, settlement notices, canonical backups, semantic restore equality, and concurrent primary assignment. Add database append-only enforcement with compatible restore ordering.
2. Preserve decision integrity. Fix same-line shopping, anchor-only market comparisons, shopped timestamps, and forecast eligibility independent of drafting. Repair the single-offer forecast path, datetime interpretation, protocol preflight, and synthetic replacement default.
3. Repair runtime and UI behavior. Bound body consumption, sanitize provider errors before storage, scope form results, update theme state, fix native refresh submission, and apply the confirmed visual corrections. Add LAN protection when used.
4. Change model inputs and anchors through a reviewed artifact revision. Correct PROE and the declared play sample, invalidate summary caches, refit, test anchor calibration, and register the new predictive identity.
5. Design prospective evaluation changes separately. Specify moved-line inference, independent push diagnostics, closing provenance, and release identity before collecting qualifying evidence. Keep protocol v1 results interpretable.
6. Batch queries and add workflow reporting once record integrity is covered. Measure the actual journal before claiming a latency improvement.

The supplied review supports substantial implementation work. It does not support applying every proposed mathematical change as written or claiming that those changes will produce profitable NFL picks.
