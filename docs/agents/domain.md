# Domain docs

## Layout and reading rules

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs relevant
to the work. If they are absent, proceed silently. Domain-modeling
creates them as terms and decisions are resolved.

## Vocabulary

Use the glossary's terms when naming domain concepts in issues,
proposals, hypotheses, and tests. Reconsider unfamiliar synonyms;
note real vocabulary gaps for domain-modeling.

## Decisions

Explicitly flag proposals that contradict an existing ADR,
identify that ADR, and explain why its decision merits reopening.
